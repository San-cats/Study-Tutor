# 踩坑记录（每一个坑都是学费）

## 拼写错误类（每个都让程序死过）

| 错误写法 | 正确写法 | 当时现象 |
|---------|---------|---------|
| `"context"` | `"content"` | API 不认字段 |
| `"descripiton"` | `"description"` | 工具说明失效 |
| `"sysytem"` | `"system"` | 人设失效，AI 行为不对 |
| `"utf_8"` | `"utf-8"` | 能用但非标准 |

**教训：API 字段名一个字母都不能错。报错时先逐字母核对拼写。**

## 结构错误类

| 错误 | 现象 | 修法 |
|------|------|------|
| `required` 写在 `properties` 里面 | API 400：`["path"] is not of types` | required 和 properties 平级 |
| `else` 挂在 for 上而不是 if 上 | 循环一轮就断，打印 None | 缩进对齐 if |
| 循环体里还用 `[0]` 不用循环变量 tc | 多次调用时重复处理第一次 | 循环体里用 tc |
| 内层 while 没有 break | 无限刷屏，API 费用燃烧 | Agent 循环的 else 分支必须 break |
| 文件末尾没有 `if __name__ == "__main__": main()` | 运行毫无反应 | 补上启动按钮 |
| 调用传 3 个参数，定义只收 2 个 | ValueError: not enough values to unpack | 参数按位置对号入座，不看变量名；改函数签名后核对所有调用点 |
| tool 消息前面没有配对的 tool_calls | 400：Messages with role 'tool' must be a response to a preceding message with 'tool_calls' | tool 消息和它的 tool_calls 是连体婴儿；切片/过滤别拆散，分类器用 chat_view 滤掉施工层 |
| HISTORY 里存入 message 对象没转字典 | TypeError: 'ChatCompletionMessage' object is not subscriptable | 入账前 `.model_dump()`，账本里只存纯 dict |
| `append()` 一次传两个参数 | TypeError: append() takes exactly one argument | 一次只记一条账 |
| 环境变量名和 .env 里对不上 | OpenAIError: Missing credentials | getenv 的名字和 .env 逐字对（对账法：两串并排找茬） |
| A import B 且 B import A | ImportError: partially initialized module (circular import) | 依赖方向单向：工具箱不认识使用者 |
| 工具名三处不一致（示例/schema/分派表） | KeyError: 工具名 | schema 的 name 和分派表的 key 是一对钥匙锁，改一处查三处 |
| 函数里 `+=` 全局变量没声明 global | UnboundLocalError | 函数里赋值 = 声明局部；想改外面的先 `global` |
| `from 模块 import 变量`（数字/字符串） | 值永远停在 import 那一刻（复印件） | 不可变对象跨模块 import 必冻；只 import 收银台函数，每次调用现查 |
| 收银台函数建在调用方 | 返回的仍是复印件 | 收银台开在账本主人家里；谁产生的 token 记谁家，别家走函数问 |
| 分支里用了另一个分支才定义的变量 | NameError: name 'xxx' is not defined | 变量只活在定义它的分支里；共用变量提到分支外，写完先跑一遍再交 |
| 变量名 sum 遮蔽内置函数 | 之后调 sum() 报 int 不可调用 | 别拿内置函数名当变量名 |

**教训：嵌套结构的缩进 = 逻辑结构。改代码先看缩进对齐。**

## 概念混淆类

| 混淆 | 区别 |
|------|------|
| print vs return | print 显示给人看（返回 None）；return 交出值 |
| strip vs split | strip 剥空白（返回字符串）；split 劈列表 |
| 字符串比较 vs 数字比较 | "10" < "9"（字典序）；10 > 9 |
| `d[key]` vs `d.get(key, 默认)` | 前者键不存在就 KeyError；后者安全 |

## 逻辑错误类

| 错误 | 当时现象 |
|------|---------|
| 删文件判断反了（isdir 为真才删） | 删文件被拒绝，删文件夹报错 |
| `num[char]` 和 `char.lower()` 混用 | "Success" 大写 S 触发 KeyError |
| 工具执行后没把结果发回 AI 再问 | AI 只能瞎编，打印 None |
| 判断结果存回原变量（`line = line.strip().startswith("#")`） | 列表里存的变成 True/False，原文字永远丢失 | 判断结果用新变量装：`is_heading = ...`；一行里既读又写同一个变量是危险动作 |
| 第二次请求不带 tools | AI 想调工具也调不了 |
| 工具函数忘 return | AI 收到 "None"，一脸懵 |
| 记忆只记账不查账 | 追问"再+3呢"AI 答不上来 | 记账的同时要把 HISTORY 拼进 API 的 messages |
| 分类器被上下文带偏（叛变） | 该输出 JSON 时输出聊天回复（JSONDecodeError） | 模仿压过指令：提示词加固（身份隔离+反叛变条款+标签包裹）+ try/except 兜底 |

## 环境类

| 坑 | 解法 |
|----|------|
| 中文 Windows 控制台 GBK 报错/乱码 | 文件头 `# -*- coding: utf-8 -*-`；emoji 会炸，用 [OK]/[FAIL] 代替 |
| pip 装包超时/找不到 | 加清华镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| PowerShell 禁止运行脚本 | `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` |
| PyCharm 解释器指错（Anaconda 抢） | Settings → Project → Python Interpreter 手动指向 venv |
| .env 找不到 | 路径层级数对（往上几层就 dirname 几次，或直接写死） |
| 路径带空格（F:\AI agent） | 命令行里加引号 `cd "F:\AI agent"` |
| .env / venv 被 git 跟踪 | 密钥和几千个库文件进了仓库 | 根目录建 .gitignore（.env、venv/、__pycache__/、.idea/），再 `git rm -r --cached .` + `git add .` 重新登记 |

## 安全类（职业铁律）

**密钥一旦进过 git 历史，就当它已经泄露。** commit 是永久档案，删文件也删不掉历史。仓库 push 到 GitHub 之前，先去平台把 key 重新生成一个（换锁）。密钥 = 银行卡密码：不进代码、不进截图、只进 .env。

- **GitHub push protection 扫整个历史**：换完锁 push 仍被拦——它不认"锁已换"，只认历史里的死钥匙。完整流程：**换锁 → 清尸 → 才见光**
- 清尸（仓库从未 push 过才安全）：`git filter-branch --force --index-filter "git rm --cached --ignore-unmatch .env" --prune-empty -- --all` → `rm -rf .git/refs/original` → `git reflog expire --expire=now --all` → `git gc --prune=now`；验尸：`git log --all --oneline -- .env` 应为空，再 `git log -p --all | grep -oE "sk-[A-Za-z0-9]{20,}"` 确认无真实密钥（占位符 sk-xxx… 无害）

## 调试心法

1. **探针打印**：不确定哪里错，就在关键位置 print 看实际值
2. **先翻译报错最后一行**：英文报错最后一行是核心信息
3. **跑起来验证，别用眼睛看代码**：AI 有没有真调工具，看探针打印几次
4. **小步测试**：写完一个函数就测，别等全写完
5. **修复分两层**：提示词治本（降低失手概率）+ 代码兜底（失手也不崩）。只装兜底不治病 = 静默做错事
