# 06 提示词工程与意图路由器（stage04）

## 一、提示词工程五零件

| 零件 | 作用 | 例子 |
|------|------|------|
| 角色 | 告诉模型"你是谁" | 你是意图分类器 |
| 任务 | 让它干什么 | 判断用户输入属于哪个意图 |
| 背景 | 给它判断依据 | 可选类别：math / chat / knowledge |
| 格式 | 约束输出长什么样 | 只输出一行 JSON |
| 示例 | 手把手教（few-shot） | 输入:5+8 → 输出:{"intent":"math"} |

**原理：模型看提示词 = 员工看岗位说明书。五个零件写齐，它才知道演什么角色、交什么答卷。缺角色它自由发挥，缺格式它交小作文。**

## 二、输出合同：JSON 化

- 用 JSON 约束输出 = 和模型签"格式合同"，程序才能 `json.loads` 解析
- few-shot 示例（几个输入输出对）比干巴巴的描述有效得多
- 两个坑：
  - **占位符会被照抄**：示例写 `{"intent": "类别"}`，模型就真输出"类别"——示例里要写真值
  - **禁止条款要具体**：光说"只输出JSON"不够，要补"禁止解释、禁止markdown代码块、禁止表情"

## 三、意图路由器 = 分类 + 分派 + 记忆

```
classify(分类) → DISPATCH[intent](分派) → handle_xxx(执行+记账)
```

- **DISPATCH 分派表**：第三次见到这个模式（名字→函数对象），意图和处理器解耦，加新意图只加一行
- **分类器是无状态的**：它记不住上一轮聊了什么，所以追问"那它有什么缺点"会迷路——必须把 HISTORY 塞给它当上下文
- **指代词**（它/那/再）是路由触发器：看到指代词就必须结合上文判断

## 四、记忆账本：从分账到总账

| 阶段 | 设计 | 问题 |
|------|------|------|
| 设计A（分账） | 每个子系统各记各的 | 跨分支追问迷路（math 的账 chat 看不见） |
| 设计B（总账） | conversation.py 一个 HISTORY | 全局共享，追问有上文 |

- append 的两种目的：**跨轮记忆**（追问要用）vs **单轮流水账**（工具调用施工记录）
- **死记忆**：只记账不查账——记账没用，把 HISTORY 拼进 API 的 messages 才算查账
- 记账时机：调用 API 之后记，user 和 assistant 两条都记

## 五、模块化重构（stage04 重点）

| 文件 | 职责（单一职责原则） |
|------|------|
| llm.py | 公共设施：两个 client |
| conversation.py | 公共账本：HISTORY |
| math_tools.py / chat_tools.py / knowledge_tools.py | 三个子系统 |
| main.py | 分类器 + 分派 + 主循环（只当调度员） |

- **import 会执行整个文件**：所以直接 import 旧文件会连它的输出一起跑——库文件要用 `if __name__ == "__main__"` 守卫

## 六、消息形态统一

- API 返回的 message 是对象，HISTORY 里要存纯 dict → `.model_dump()`
- **tool 消息必须紧跟在配对的 tool_calls 后面**（连体婴儿）；切片/过滤时别拆散
- 分类器只要"成品对话层"：滤掉 role=tool 和带 tool_calls 的施工消息

## 七、模仿压过指令（分类器叛变实录）★最难忘的一课

**现象**：HISTORY 里有了闲聊记录后，分类器不再输出 JSON，开始模仿聊天（"你叫小王呀！😊"），连"RAG是什么意思"都直接回答——全靠 try/except 兜底续命，路由器名存实亡。

**原理**：上下文里的对话模式对模型的诱惑力 > system 指令。模型最擅长模仿，看到上文里有个热情聊天的助手，就忍不住变成它。

**两层修复**：
1. **提示词加固（治本）**：
   - 身份隔离：你是分类器，不是对话助手
   - 反叛变条款：即使上文在聊天，你依然只输出 JSON——你不是上文里的那个助手
   - 标签包裹：把上文放进 `[对话上文]...[/对话上文]`，划清"资料"和"任务"的界限
2. **代码兜底（急救）**：try/except + 默认值 chat + 警告留痕——失手了系统也不崩

**教训：修复永远分两层。只装兜底不治病，系统会"静默地做错事"，比崩溃更危险。**

## 八、降级链：知识分支的三级回答策略

| 级别 | 来源 | 要求 |
|------|------|------|
| ① | 参考资料 | 优先，忠实，不编造 |
| ② | 上文对话 | 资料没有时参考 |
| ③ | 自身知识 | 可以答，但要标注"这不是来自你的资料"（来源透明） |

- RAG 的 A = **Augmented（增强），不是替代**——资料是给模型加 buff，不是把模型关进牢笼
- "只/必须/禁止"是绝对命令，模型宁可不答也不违反；把"只"换成"优先"就解开了牢笼
- 降级链和分类器兜底是同一个思想：每一层都有下一层接着
