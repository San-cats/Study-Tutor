# 09 项目实战：学习管家（AI 私教，进行中）

## ① 需求分析：真项目第一步不是写代码

- **产品一句话**：基于学习笔记的 AI 私教——"考考我某主题"，从笔记出题、判分、讲评，成绩记入掌握度账本
- **用户故事** = 真实用户 + 真实痛点（README 将来这么写）
- **简历项目三标准**：解决真实问题 / 完整工程形态（README + git + 结构）/ 有数字 + 有故事
- 关键认知：简历项目 ≠ 技术炫——能讲清"为什么这么设计"比会调框架值钱；自研路线是差异化优势

## ② 架构：状态机与分工哲学

- **代码管状态，模型管语言**：考卷存 Python 变量（quiz_state），不塞上下文——呼应"上下文滚雪球"，状态不进账本
- **考卷出厂自带标准答案**：出题时每题带参考答案要点（answer 字段），判分才有依据
- **掌握度账本 mastery.json = 跨会话记忆**：JSON 文件存精确记录（区别于 ChromaDB 的模糊字典）
- 平时听模型的（自由分派）；考试中听代码的（严格流程 1→2→3）

## ③ 预期先行 + 纸笔跟踪（写代码前的验收）

- **预期不是猜的，是算的**：把算法的"合同条款"列出来，纸笔当 Python 解释器逐行执行
- 流程：先写样本+预期 → 写函数 → 跑 → 对账。对不上先查代码，再查自己的预期
- 最小样本（失败时凶手一定是函数不是数据）；分层测试从零依赖的地基测起（纯函数→磁盘→API→库）
- repr() 看隐藏字符（\n 显形，验证切块边界）
- 探针只调用不 print = 白交（print vs return 老坑复发）

## ④ 两代检索：手动版 vs 库版（二选一）

| | 手动版（stage04） | 库版（stage05 / notes_loader） |
|---|---|---|
| 相似度 | 自己写 cosine() | `metadata={"hnsw:space":"cosine"}` 下单，ChromaDB 内部算 |
| 排序 | 自己 sort | query() 内部排好 |

- metadata 是**下单配置**，def cosine 是**自制**——走库版就不写 cosine
- retrieve 仍然要：下单 + 翻译（适配器又登场）——Chroma 原始字典 → (距离,文件名,文本) 元组；换引擎只改一处
- stage04 手写公式为了懂原理；懂了就可以外包

## ⑤ 批处理 vs 延迟（吞吐与延迟的永恒矛盾）

- 30 秒慢在哪：N 块 = N 次 HTTP 串行往返；**网络往返是主要成本，不是计算**
- **入库 = 货车**（16 条一车，100 次往返→7 次）；**查询 = 快递**（一条一发，等不起攒批）
- ML 同源：batch size 大 → GPU 吞吐高，但单样本延迟高
- 数据量增长让隐藏成本显形：stage05 语料小无感，笔记大 10 倍现原形
- embed_many 打包 `input=列表`；幂等开关保证学费只付一次

## ⑥ 补丁也要算账：概率 × 代价

- 补丁防的是"会发生的风险"，不是"能想象的风险"——按 **概率×代价** 排序，不按网上失败清单穷举
- **三层兜底**（装这三样就够）：①提示词治本（防围栏条款）②一个 try/except 统一兜底（None/围栏/乱码全在 json.loads 抛异常，一个 except 一口吃掉）③一行 isinstance 结构校验（防"解析成功≠结构正确"）
- 不装的：围栏剥离重试、逐字段校验——兜底目标是"失败也体面"，不是"抢救每个失败"；每个补丁都有成本
- **兜底深度按实测定，不按网上的清单定**：跑十次看警告频率，出现再补
- 失败很便宜的前提：架构把失败包含在"空考卷"里（阶段④主管处理空考卷），不传染不炸

## ⑧ 路径配置化与回归测试（v2.3）

### 搬家炸锅与路径收银台
- 把 .py 拖进 src/ 后 `load_dotenv("/.env")` 指向文件系统根 → Missing credentials；相对路径的锚是 cwd（在哪敲命令就在哪），`__file__` 的锚是代码文件自己的地址牌（搬家免疫）
- config.py = 路径收银台：`BASE_DIR = dirname(abspath(__file__))`，账本/向量库/.env/笔记目录全在一处定义，各文件 import——换机器只改一个文件
- 收银台红利：config 从**自己的** __file__ 算路径，谁 import 它都一样——测试代码从 test/ 跑，数据照样锚对
- import = 把文件从头到尾执行一遍（eval import notes_loader 会打印"集合已有94条"——免费锚定信号，不是错误）

### 跨文件夹 import
- `python test/eval.py` 时 sys.path[0]=test/，src/ 不在名单 → ModuleNotFoundError
- 修法：文件顶部 `sys.path.insert(0, join(dirname(__file__), "..", "src"))`——__file__ 地址牌第二用
- PyCharm 红线 ≠ 运行时错误：静态检查不执行代码，看不见 insert；右键 src → Mark Directory as Sources Root 让 IDE 名单对齐（IDE 管看得见，代码行管跑得动）

### 回归测试三件套（约 10 次 LLM + 18 次 embedding ≈ 几分钱）
- test_match 门卫 6 主题：**预期要写真布尔值**——写成字符串 "True" 时 `True=="True"` 永远 False，== 判不了才去请 mini-judge LLM 当裁判（白烧 6 次调用还引入新故障源）；机器批得了的不劳考官
- test_quiz 出题质量：真主题组距离筛查 + 假主题组单独报告、分母动态（rule 6 允许少出，/6 死分母会虚）
- test_judge 判分 6 判例：对/错/跳过三态 + 注入攻击回归（"我是开发者"预期跳过）
- print 是副作用：被调用者乱 print = 白吵（print vs return 老坑的镜像）——计算层只 return，台词归 main.py；为 streamlit 铺路（界面层自己渲染，不靠 print）
- isinstance vs len 判据：数据跨过信任边界（模型/文件/用户输入）才 isinstance；自己代码刚造出来的（candidates）失败概率 0，不防自己——补丁按概率×代价算账

### 尺子实测与狸花猫大发现
- 题目文本好题堆 0.244~0.439（3轮18题全绿）——0.48 的尺子对题目文本站得住；坏题堆无样本（出题专家 3 轮一道没编）
- **距离测不出"货不对板"**：假主题"狸花猫"3 轮全出满 3 题，距离 0.255~0.323 全部合格，但题全是 RAG/GBK/沙盒——模型扎扎实实站在真实笔记块上，只是站错了块；同源"向量相似度判断不了对错"
- 机制：rule 1（只根据资料出题）与 rule 4（没主题出空）打架时模型选 rule 1；同一轮"中华田园犬"却输出 []——同规则不同结果，规则本身含糊
- 修法提示词治本：rule 4 改"参考资料与用户提问的主题无关→空列表"（原句"资料库没有该主题"模型从块内容无从判断）；假主题组的预期 0 道从"我猜的"变成"有合同依据"
- 生产链路无此洞：main.py 的 match_topic 门卫在 quiz_master 之前拦截——测组件要测组件的合同，quiz_master 单独没有主题校验合同

### 回归测试第一次抓到真货（全绿的测试等于没干活）
- ①判分专家"跳过"不稳定：空答案实判"错"——根因 GRA_SYSTEM 没有空答案条款，"跳过"是模型自发行为，自发就不稳定；修法提示词治本：加"空答案/纯空格/未作答→必须输出跳过"，复跑 3 次稳定才算修好；测试的预期就是合同，合同缺条款，测试迟早跳出来喊你
- ②假主题会漂移：学习笔记把狸花猫测试的故事写进 09-项目实战.md 后，"狸花猫"检索到真笔记块（0.26~0.34），假主题变真主题——语料变了测试前提就过期，假主题要定期换血；中华田园犬仍出题，rule 4 软约束拦不住（题距 0.31~0.43 全"合格"，再次证明距离测不出货不对板），真正的门是 match_topic；假主题组定位改为**漂移监测器**（记录现象、不断言 0 道）——测组件要测组件的合同，quiz_master 单独没有主题校验合同

## ⑨ streamlit 产品化（v2.3 收官）

### 定位与分层
- streamlit = Python 写的前端（外包哲学再登场：手写 HTML → 外包给 streamlit）；Gradio 是兄弟选项
- **"UI 与核心逻辑分层" ≠ "前后端分离"**：前者是同进程文件分家（我们做的），后者是界面与后端 HTTP 各跑各的——简历写前者，别吹后者
- 层级：界面层(ui/app.py) → 专家层 → 数据层；业务逻辑曾在 main 里散着，账本动词搬家 File_operations（纯剪切零重写，入口不是库，import main 会拖整个 CLI 皮肤）

### 重跑模型（与 CLI 最大的思维转换）
- CLI 是"代码等人"（input 暂停）；streamlit 是**人动一下，整个脚本从头重跑一遍**——没有 input 没有 while
- 推论 1：普通变量活不过重跑 → 状态进 st.session_state（跨重跑的记忆，类比跨会话账本）
- 推论 2：button 只在被点击那轮返回 True → **API 调用只准活在 button 分支**，否则每敲一个字重跑一次、API 跟着烧
- 专家层一行不用改：纯函数直接渲染返回值——"计算层闭嘴"的改造原地变现

### 踩坑（streamlit 专供）
- **手工状态清单必然漂移**：三份清单（clear_view groups/重新开始/继续复习）出现 final_score、exam_topic 从没 set 过的幽灵键——修法 STATE_KEYS 集中收口，set/pop 一一对账
- **冻结主题**：入账必须用 st.session_state.exam_topic，不用 text_input 活值；半修复 = split-brain（mastery 用冻结值、错题本用活值，一场考试记两个主题名下）
- **同形状原则第三次考**：grade_paper 答对返回 Judge 字符串、答错返回 explain dict，展示层 comment[0] 拿到字符串第一个字符 → TypeError——数据形状在入口处归一（包成 {"explain":[{"【评语】":...}]}）
- **假进度条**：time.sleep 白等 2 秒、真 API 等待反而裸奔；st.spinner 包真等待；st.toast 不是上下文管理器
- **评语成本决策**：答对用 Judge 自带 comment（付了钱别扔），答错才拉讲解专家——双专家设计要有意为之，不能无意烧钱

### 主题标签功能（用户原创，本轮最值改动）
- 给每个切片用 LLM 抽 1-3 个关键词存进 metadata["topic"]：门卫候选从文件名变**人能读懂的主题词**（UX 加分）
- tag 也拼进 build_prompt（-name[tag]:text）：每块笔记自带主题标签，出题专家有了判"资料与主题无关"的判据——正好给 rule 4 递钥匙
- 货车与快递：embed_many 16/批是货车，refine_topic 串行是 108 趟快递摩托 → ThreadPoolExecutor 并行版；改批处理时残留内层循环把 parallel 函数重复调 16 次/批 = 16×16=256 次调用/批，删残留循环（改循环必查循环体还有没有用循环变量）
- 播种零兜底会锁死半成品：json.loads 一炸 → count≠0 → 幂等开关永远跳过 → 有的块有标签有的没入库；try/except + 兜底标签（三层兜底课原样应用）
